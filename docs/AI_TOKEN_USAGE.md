# 維持 AI 分析，減少重複 token

AI 是新任務的判斷方式。實驗瀏覽快照也使用 AI，不會因 API 未設定、費用預算或分析失敗而降級成關鍵字推薦。以下措施減少不必要的請求，不以關閉 AI 取代分析。

## 分析順序

1. 先以本機程式檢查關鍵字、價格範圍、排除字詞及其他可用條件。明確不符合條件的商品不送 AI。
2. 完整保存這次通過篩選的商品批次與價格歷史，再開始可失敗的 AI 呼叫。舊的顯示結果先清除，避免條件修改後沿用舊判斷。
3. 查找同一任務、來源、商品的有效分析指紋。符合時直接重用之前的 AI 結果，不重新產生。
4. 沒有有效快取時才呼叫 AI。只有通過嚴格 JSON 型別與證據檢查的結果可保存為快取。不推薦的有效判斷也可重用；錯誤、空白、截斷或不合法 JSON 不會當作推薦。
5. 重用的結果也重新驗證，並由 `is_recommended` 布林值產生介面顯示。Discord 仍沿用商品／價格去重，不會因重用分析而重複通知。

缺少 API Key、模型或端點設定時顯示錯誤，商品仍保存。關鍵字模式只保留既有任務相容性，不是本次節省 token 的替代方案。

## 什麼變更需要重新分析

指紋使用 SHA-256，涵蓋：

- 商品價格、標題、完整描述、賣家資料、條件、來源、資料品質及圖片分享權限等穩定欄位。即使描述修改發生在省略部分，也會重新分析。
- 任務需求、關鍵字／價格／排除條件、自訂 Prompt、是否分析圖片。
- 基礎 Prompt 的完整內容、實際訊息規則及分析政策版本。
- 模型、端點路徑與非驗證查詢設定、JSON 模式、輸入與輸出預算、圖片數量上限。

重新採集時間不會造成失效。任務名稱、排程、通知設定與單次數量限制不是單件商品的購買條件，也不會造成失效。更換 API Key 不會改變分析內容指紋；仍須有完整 AI 設定才能執行。

快取以本機 SQLite 保存，每個任務／來源／商品只保留最近一份成功結果。重啟後可重用，不會無限累積每個 Prompt 版本。舊資料與歷史執行紀錄以新增式遷移保留。資料庫仍是私人檔案，不應加入 Git 或公開分享。

快取只保存指紋與有效分析結果，不保存整份 AI 連線設定、API Key、密碼或 token。端點中的帳密與常見驗證查詢參數不加入指紋；請仍使用不含機密的 Base URL。

## 輸入與圖片預算

AI 只收到分析所需的固定欄位：商品識別、標題、TWD 價格、條件、描述、分類、廣告標記、資料來源／品質與可查證的賣家評分、評價數、所在地及類型。省略賣家暱稱、商品連結、採集時間及其他非判斷欄位。

- 預設描述上限為 **2000 字元**。完整原文仍保存在本機；送出的資料標示 `description_truncated`，Prompt 明確要求不得推定省略內容。
- 標題、分類與賣家文字欄位各自設上限。JSON 採緊湊格式，不加不必要縮排。
- 使用者需求不重複附加。需求和自訂 Prompt 不會靜默截斷；合併後超過預算便顯示 `ai_prompt_too_large`，請精簡後重試。
- 圖片預設未勾選。只有任務勾選圖片分析，且商品資料明確允許圖片分享，才傳送核准的公開 HTTPS 圖片。預設每件最多 **2 張**，可調整到 4 張。文字 JSON 的 `images` 永遠是空陣列，避免未授權網址混入文字。
- 伺服器不下載遠端圖片。允許的網址經安全檢查後才交給模型；圖片數量上限不代表已授權分享。

字元上限不是 token 計數。中文、英文、模型分詞與圖片解析度都影響實際用量，不能把字元數或圖片數當成計費估算。

## 可調整的 `.env` 設定

| 設定 | 預設 | 範圍／用途 |
| --- | ---: | --- |
| `AI_MAX_OUTPUT_TOKENS` | 1200 | 256–4000，每次 API 請求的輸出預算 |
| `AI_PRODUCT_DESCRIPTION_CHARS` | 2000 | 256–4000，商品描述字元上限 |
| `AI_MAX_IMAGES` | 2 | 0–4，已獲允許時的單件圖片上限 |
| `AI_MAX_PROMPT_CHARS` | 12000 | 2000–40000，基礎規則＋需求＋自訂 Prompt 上限 |
| `AI_EMPTY_RESPONSE_RETRIES` | 0 | 0 或 1；空白回覆預設不重試 |

修改後重新啟動伺服器最容易確認設定已套用。圖片勾選不會被這些設定自動打開；將圖片上限設為 0 會停用圖片傳送，但仍保留文字 AI 分析。

推理模型可能將推理用量算入 `max_completion_tokens`，過小預算可能沒有可用 JSON。遇到此情形可手動提高輸出上限，不會自動放大預算或無限重試。SDK 的隱藏自動重試已關閉；明確的 API 參數不相容仍可做有界調整，保留 Chat Completions／Responses、token 欄位、JSON 和 temperature 相容性。

## 執行紀錄

每次執行回傳並保存以下欄位，無原始 Prompt、請求內容或機密：

- `ai_new_count`：實際進入 `client.analyze()` 的新分析嘗試件數，包含最後分析失敗的商品。
- `ai_reused_count`：成功驗證並重用的 AI 分析件數。
- `ai_skipped_count`：監控服務收到後未呼叫 AI 的件數，例如本機篩選排除、缺少設定、Prompt 超出預算，以及既有明確關鍵字任務。

資料來源可能已經做過初步篩選。因此「略過」只計算監控服務收到的商品，不是整個匯入檔或網站的排除總數。執行逾時或取消時，尚未走到分析步驟的商品也不會冒稱已分析／略過。

這是商品層級的工作計數，**不是實際 HTTP 請求數、token 用量或帳單**。單件分析可能有參數相容性調整；供應商計費仍以其用量紀錄為準。

## 離線驗證

`tests/unit/test_ai_token_policy.py` 以假資料來源與假 AI 用戶端驗證：跨重啟重用、各類失效條件、完整批次保存、失敗不快取、輸入上限、圖片權限、通知去重及資料庫新增式遷移。其他 AI 測試涵蓋嚴格 JSON／證據規則和端點相容性。

測試不連接真實 AI、蝦皮或 Discord。尚未由這些測試證明任何供應商實際節省比例、模型品質或帳單金額。
